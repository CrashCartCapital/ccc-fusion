# DuckLake v7.2.3 Blocking Test Index

This is the authoritative flat index of every named acceptance test in the v7.2.3 module set (FBL2-07), built by exhaustive extraction from the owner modules. `task verify:phase0-index` MUST diff the generated `docs/implementation-index.seed.csv` blocking rows clean against this file's `verify:phase0`-union rows; the agent-generated seed is never its own authority. This file is PRD authority for test NAMES, PHASE routing, and OWNERSHIP only; each test's acceptance criteria stay in its owner module.

## Column Semantics

- `name` — the exact pytest test name (the header deliberately avoids a `test_`-prefixed column name so the coordinator token count stays artifact-free). The 291 figure is the base-row component inherited from the FBL2 extraction, not the current CSV total; those base rows appear exactly once, including the three documented alias names (`test_sec_accepted_at_controls_availability`, `test_backfill_amnesia_prevention`, `test_feature_known_at_is_max_input_availability`), which share one implementation each with their canonical siblings. The wildcard prefix token `test_sql_gateway_` is a count artifact, not a test, and is excluded; the current authoritative total is the 419-row CSV count statement below.
- `phase` — one of `phase0`, `phase0_gated_xfail`, `phase1`, `phase1b`, `prelive`, `multi_host_prelive`, `retrieval`, `future_sql`, `adjustment_gated`. The `task verify:phase0` union is exactly the `phase0` rows plus the `phase0_gated_xfail` rows (the latter collected as `xfail(strict=True)`). Phases map onto the closed pytest marker vocabulary one-to-one: `phase0_gated_xfail`→`iface_gated`, `phase1b`→`options`, and `multi_host_prelive`→`multi_host_prelive`; all other phases map to the same-named marker.
- `owner_module` — the module whose section owns the requirement behind the test; shared tests carry their primary owner per the OwnershipMap.

## Adjudicated Phase Rulings

Rulings applied where module text left phase ambiguous (recorded in [[REF-AI-DuckLake-v7.2.3-AdjudicationLedger]]): `test_run_event_and_failed_run_diagnosis_schema_validate` and `test_secret_redaction_across_logs_artifacts_manifests_profiles` are `phase0` (the Phase 0 proof harness requires event schemas and fake-secret redaction tests), while the storage-probe, DSN-classifier-topology, launch-posture, retention, permission-probe, cleanup-delete-approval, and proven-publish tests are `prelive`. `test_retrieval_deferred_until_enabled` is `phase0` (an absence guard). Decimal-strike key-derivation tests are `phase0` (pure functions needing no adapter). Adjustment-math-dependent tests are `adjustment_gated` because Phase 0 adjustment functions are `NotImplementedError` stubs (QD7). A skipped, xfail, stale, unavailable, or quarantine-only publish proof cannot satisfy pre-live. The three planning-note tests from [[REF-AI-CCC-DuckLake-v7.2.3-Source-Universe-Planning]] are `phase1` (they open with `task verify:source-adapter-gate`).
