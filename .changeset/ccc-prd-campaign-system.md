summary: Add the CCC PRD campaign system — deterministic packet compiler, PostgreSQL import, and the `fn prd` CLI surface.
category: feature
dev: New `packages/engine/src/ccc-prd/` (authoring, compiler) and `packages/core/src/ccc-prd/` (contract, importer, projection) implement a manifest-scoped campaign pipeline: native/deterministic authoring produces a versioned candidate sidecar with a bounded ambiguity/exception/protected-decision review payload, `compile`/`validate` re-derive and check the sidecar against the manifest and expected target/base, and `importCccPrdBundle` lands the compiled bundle onto the task board with idempotency-keyed transactional writes and restart/reconciliation recovery. Execution runs behind fail-closed proof admission (`ccc-campaign-proof-admission.ts`/`ccc-campaign-proof-host.ts`, migration 0036), sealed provider dispatch through `ccc-campaign-provider-controller.ts`, and canonical protected-action ID enforcement at both authoring and validation. Landing onto git is fail-closed (`ccc-campaign-git-landing.ts`/`ccc-campaign-local-git.ts`) and merge/admission for imported campaign tasks routes through dedicated drift checks (`ccc-campaign-merge-control.ts`/`ccc-campaign-admission.ts`) instead of the general merge path. The Wave 6 proof-runner mapping in `scripts/run-ccc-pg-proof.mjs` is closed with provenance attestation over the exact scrubbed git state each proof run attests to. CLI surface documented in `docs/cli-reference.md` (PRD campaign / `fn prd`); fork-divergence rationale and owning surfaces recorded in `docs/divergence-ledger.md`.
