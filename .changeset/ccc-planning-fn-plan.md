summary: fn plan starts, inspects, answers and controls a request-to-code planning run with exit codes 0, 1 and 2.
category: feature
dev: New fn plan command, routed by bin.ts before the bin-level --project parse so plan.ts owns every usage error. Grammar: fn plan start, status RUN_ID, answer RUN_ID, pause, cancel and resume RUN_ID, build RUN_ID and budget RUN_ID, with the run id positional and --project optional (resolved from the run row, RUN_AMBIGUOUS and RUN_PROJECT_MISMATCH otherwise). With --json stdout holds exactly one ccc-planning.cli.v1 line (status, control_accepted, answer_accepted, refusal or usage_error); exit 0 is success, 1 a refusal and 2 a usage error, and an unexpected error is a CCC_PLANNING_INTERNAL_ERROR refusal that never uses FUSION_NON_RETRYABLE_EXIT_CODE. --actor defaults to the OS user, is trimmed and must be 1 to 200 characters. A linked run routes pause, cancel and resume through deps.applyBuildControl, which refuses with CCC_PLANNING_COMMAND_NOT_SUPPORTED until the build control bridge is wired; build and budget are refused the same way until I4, and a well-formed start is refused until fn plan start is wired. The plan route returns before bin's shutdown tail, so it closes the global settings revision layers itself in a finally (best effort, never changing the exit code); without that a stale default project made fn plan status hang on an embedded PostgreSQL nothing closed.
