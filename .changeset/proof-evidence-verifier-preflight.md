summary: Refuse a non-conforming proof verifier at preview/import instead of only after a live task burns a real attempt.
category: feature
dev: `fn prd preview`/`fn prd import` now run every declared v2 proof's verify command against the pinned base commit, in the same sealed materialize-then-sandbox path a live attempt uses (`admitAndMaterializeCccSemanticProof` + `verifyCccSemanticProofToolchainBeforeSpawn` + the semantic-proof sandbox), and judge stdout with the exact same `parseSemanticProofEvidence`/`semanticProofEnvelope` a live proof attempt uses — never a second parser. No candidate implementation exists yet at preview/import time, so materialization gained an opt-in `allowMissingCandidates` flag (default `false`, unchanged for the real per-attempt path) that tolerates an absent candidate blob instead of refusing outright; a conforming verifier must still emit valid `ccc-prd.proof-evidence.v2` JSON in that state. A refusal now surfaces the structured code `CCC_PRD_PROOF_VERIFIER_NONCONFORMING`, naming the proof, the parse warning, the first line of stdout, and a bounded stderr excerpt. Also splits the evidence-parser's collapsed `not-canonical-json` reason into `not-json` (stdout was never JSON syntax at all) and `not-canonical-json` (a successful parse that is merely non-canonical byte form) — the two are different defect classes and the collapsed reason hid a verifier that never emits the contract behind what read as a formatting nit.

The preflight's sandbox policy is now the exact same function the live per-attempt path builds its policy from (`semanticProofSandboxPolicyFor`, shared by both callers instead of a parallel copy) — the parallel copy had omitted the host Python deny-roots the live path denies, so a verifier that leaned on host site-packages could have passed preview and only failed for real once dispatched. The toolchain is now sealed exactly once per proof, not once per declared phase, matching the live path's once-per-attempt sealing without changing the independent 300s-per-phase run bound.

`fn prd preview`/`fn prd import` gate the preflight, and the preview payload's `verifierConformanceChecked` field, on the readiness of the semantic-proof-v2 sandbox specifically (`inspectCccSemanticProofSandboxReadiness`, sandbox-exec only, Darwin-only today), probed once and threaded through — never on the unrelated agent-verification confinement (bubblewrap on Linux, sandbox-exec on Darwin) that an earlier revision of this preflight mistakenly gated on. Conflating the two meant a Linux host with a working bwrap sandbox would enter the preflight, hit the semantic-proof sandbox's own absence, and crash `fn prd preview` with a confusing `CCC_PRD_PROOF_VERIFIER_NONCONFORMING` refusal instead of a clean "this host lacks the backend" message. When the semantic-proof sandbox isn't ready, `fn prd preview` no longer tries to run the real preflight at all (it can't) and reports `verifierConformanceChecked: false` with a warning that the check will run again at import; `fn prd import` refuses up front using the existing verifier-confinement-unavailable refusal shape and code (`CCC_CAMPAIGN_VERIFIER_CONFINEMENT_UNAVAILABLE`), not the nonconforming code, since no verifier has been judged yet. Inside the preflight itself, an unavailable sandbox now throws a distinct `CccCampaignSemanticProofSandboxUnavailableError` (`CCC_CAMPAIGN_SEMANTIC_PROOF_SANDBOX_UNAVAILABLE`) — the same code the live per-attempt path already reports for the identical condition — instead of the verifier-nonconforming error, so the operator message never implies a working verifier is broken when the real problem is a missing host capability.
